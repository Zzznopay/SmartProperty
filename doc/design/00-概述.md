# 智能物业系统 - 设计文档概述

## 一、文档说明

本文档集为"和家云服务管理云平台"后端微服务系统的详细设计文档，基于技术栈设计文档和业务需求文档编写。

### 1.1 文档清单

| 序号 | 文档名称 | 对应服务 | 业务模块 |
|------|---------|---------|---------|
| 01 | 系统基础服务设计 | smart-property-system | 认证授权、系统管理、文件管理、报表服务 |
| 02 | 房产财务服务设计 | smart-property-property | 房产管理、业主管理、租赁管理、收费管理、车位管理 |
| 03 | 运营管理服务设计 | smart-property-operation | 服务工单、保洁绿化、消防安全、保安管理、停车管理、公告通知、意见箱、投票调查、消息中心 |
| 04 | 数据库设计规范 | - | 数据库设计标准 |
| 05 | 设计文档检查报告 | - | 完整性检查 |

### 1.3 代码规范

本项目遵循《阿里巴巴Java开发手册（泰山版）》规范，核心要点：

- **命名规范**：类名UpperCamelCase，方法名/变量名lowerCamelCase，常量全大写下划线分隔
- **分层规约**：Controller → Service → Mapper
- **领域模型**：DO（数据对象）、DTO（传输对象）、VO（展示对象）、Query（查询对象）
- **异常处理**：统一异常处理，5位错误码（A用户端/B系统端/C第三方）
- **日志规约**：SLF4J门面，占位符方式，敏感数据脱敏

### 1.4 分页规范

- 使用MyBatis-Plus分页插件 `PaginationInnerInterceptor`
- 分页参数统一：`pageNum`（页码，从1开始）、`pageSize`（每页条数）
- 返回格式：`IPage<T>` 或自定义分页响应对象

### 1.5 SQL规范

- 简单CRUD：使用MyBatis-Plus内置方法
- 复杂SQL：使用XML映射文件，存放在 `resources/mapper/` 目录
- 多表关联查询：必须使用XML，禁止在Java代码中拼接SQL

### 1.6 多租户设计

- 每张业务表包含 `company_id` 字段（物业公司ID）
- 通过MyBatis拦截器自动注入租户条件
- 网关层解析 `X-Tenant-Id` Header传递到下游
- 索引策略：`company_id` + 业务字段联合索引

## 四、统一响应格式

```java
/**
 * 统一响应对象
 */
public class Result<T> {
    private String code;        // 状态码
    private String message;     // 响应消息
    private T data;            // 响应数据
    private long timestamp;    // 时间戳
    private String traceId;    // 链路追踪ID
}

/**
 * 分页响应对象
 */
public class PageResult<T> {
    private long total;        // 总记录数
    private long pageNum;      // 当前页码
    private long pageSize;     // 每页条数
    private long pages;        // 总页数
    private List<T> records;   // 数据列表
}
```

## 五、错误码规范

| 错误码前缀 | 类型 | 说明 |
|-----------|------|------|
| A | 用户端错误 | 参数校验失败、权限不足、资源不存在等 |
| B | 系统执行错误 | 数据库异常、缓存异常、业务逻辑异常等 |
| C | 第三方服务错误 | 短信服务、支付服务、OSS服务等 |
| 00000 | 成功 | 正常返回 |
