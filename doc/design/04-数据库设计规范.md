# 数据库设计规范

## 一、命名规范

### 1.1 数据库命名

- 格式：`smart_property_{模块名}`
- 示例：

```
smart_property_system       # 系统库 (用户/角色/权限/字典/文件/报表)
smart_property_property     # 房产库 (住宅/楼宇/房间/业主/租赁/费项/收费/车位)
smart_property_operation    # 运营库 (服务单/保洁/消防/安防/停车/公告/规章/消息)
```

### 1.2 表命名

- 表名小写，单词间用下划线分隔
- 命名格式：`{模块}_{业务名称}`
- 表名不用复数
- 禁用保留字

| 模块前缀 | 说明 | 示例 |
|---------|------|------|
| sys_ | 系统模块 | sys_user, sys_role, sys_menu |
| property_ | 房产模块 | property_community, property_building |
| finance_ | 财务模块 | finance_fee_item, finance_ledger |
| operation_ | 运营模块 | operation_service_order, operation_clean_arrange |
| admin_ | 行政模块 | admin_notice, admin_survey |
| report_ | 报表模块 | report_snapshot, report_export_task |
| file_ | 文件模块 | file_info, file_folder |
| auth_ | 认证模块 | auth_token_blacklist |

### 1.3 字段命名

- 字段名小写，单词间用下划线分隔
- 布尔字段使用 `is_` 前缀，类型为 `tinyint unsigned`（1=是，0=否）
- 时间字段使用 `_time` 后缀
- 日期字段使用 `_date` 后缀
- 名称字段使用 `_name` 后缀
- 编码字段使用 `_code` 后缀

### 1.4 索引命名

| 索引类型 | 命名格式 | 示例 |
|---------|---------|------|
| 主键 | `pk_{字段名}` | pk_id |
| 唯一索引 | `uk_{字段名}` | uk_username, uk_contract_no |
| 普通索引 | `idx_{字段名}` | idx_company_id, idx_create_time |
| 联合索引 | `idx_{字段1}_{字段2}` | idx_company_id_status |

## 二、表结构规范

### 2.1 必备字段

每张业务表必须包含以下字段：

```sql
id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
company_id BIGINT UNSIGNED NOT NULL COMMENT '物业公司ID',
create_by VARCHAR(64) DEFAULT NULL COMMENT '创建者',
create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
update_by VARCHAR(64) DEFAULT NULL COMMENT '更新者',
update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
is_deleted TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '是否删除(0否 1是)',
```

### 2.2 字段类型选择

| 场景 | 推荐类型 | 说明 |
|------|---------|------|
| 主键 | BIGINT UNSIGNED AUTO_INCREMENT | 自增主键 |
| 布尔值 | TINYINT UNSIGNED | 1=是，0=否 |
| 状态 | TINYINT UNSIGNED | 使用枚举说明 |
| 金额 | DECIMAL(10,2) | 精确到分 |
| 面积 | DECIMAL(12,4) | 精确到小数点后4位 |
| 单价 | DECIMAL(10,4) | 精确到小数点后4位 |
| 手机号 | VARCHAR(32) | 加密存储 |
| 身份证 | VARCHAR(128) | 加密存储 |
| 名称 | VARCHAR(64) 或 VARCHAR(128) | 根据实际长度 |
| 地址 | VARCHAR(256) | |
| 描述/内容 | TEXT | |
| JSON数据 | JSON | MySQL 8.0+ |
| 时间 | DATETIME | 不使用TIMESTAMP |
| 日期 | DATE | |
| 时间 | TIME | |

### 2.3 字段注释规范

- 所有字段必须有COMMENT
- 枚举值必须在COMMENT中说明
- 示例：

```sql
status TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '状态(1待分配 2处理中 3待回访 4已完成 5已关闭)',
```

### 2.4 默认值规范

- NOT NULL字段必须设置默认值
- 字符串默认空字符串 `''`
- 数值默认0
- 时间默认 `CURRENT_TIMESTAMP`
- 删除标记默认0

## 三、索引规范

### 3.1 索引设计原则

- 业务唯一字段必须建唯一索引
- 常用查询字段建立普通索引
- 联合索引区分度高的字段在前
- 单表索引数量不超过5个
- 避免冗余索引

### 3.2 索引类型选择

| 场景 | 索引类型 | 说明 |
|------|---------|------|
| 主键 | PRIMARY KEY | 自增ID |
| 业务唯一 | UNIQUE KEY | 合同编号、编码等 |
| 外键关联 | INDEX | company_id、room_id等 |
| 查询条件 | INDEX | status、create_time等 |

### 3.3 联合索引设计

```sql
-- 租户隔离 + 查询条件
KEY idx_company_id_status (company_id, status)

-- 租户隔离 + 时间范围
KEY idx_company_id_create_time (company_id, create_time)
```

## 四、SQL规范

### 4.1 查询规范

- 查询不用 `*`，明确字段列表
- 分页查询count为0直接返回
- 判断NULL用 `ISNULL()`
- 多表操作列名前加表别名限定

### 4.2 更新规范

- 更新记录必须同时更新 `update_time`
- 不更新无改动字段
- 数据订正先SELECT确认

### 4.3 删除规范

- 使用逻辑删除（is_deleted字段）
- 删除前先查询确认

## 五、分页规范

### 5.1 MyBatis-Plus分页配置

```java
@Configuration
@MapperScan("com.smart.property.*.mapper")
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

### 5.2 分页查询示例

```java
// Service层
public IPage<UserVO> getUserPage(UserQuery query) {
    Page<UserVO> page = new Page<>(query.getPageNum(), query.getPageSize());
    return userMapper.selectUserPage(page, query);
}
```

### 5.3 XML分页查询

```xml
<select id="selectUserPage" resultType="com.smart.property.system.vo.UserVO">
    SELECT
        u.id, u.username, u.real_name, u.phone_mask, u.status, u.create_time, d.dept_name
    FROM sys_user u
    LEFT JOIN sys_dept d ON u.dept_id = d.id AND d.is_deleted = 0
    WHERE u.is_deleted = 0 AND u.company_id = #{companyId}
    ORDER BY u.create_time DESC
</select>
```

## 六、多租户规范

### 6.1 租户字段设计

- 所有业务表包含 `company_id` 字段
- 类型：`BIGINT UNSIGNED NOT NULL`
- 位置：主键之后

### 6.2 租户隔离配置

```java
@Configuration
public class TenantConfig {

    @Bean
    public MybatisPlusInterceptor tenantInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new TenantLineInnerInterceptor(new TenantLineHandler() {
            @Override
            public Expression getTenantId() {
                return new LongValue(TenantContextHolder.getCompanyId());
            }

            @Override
            public String getTenantIdColumn() {
                return "company_id";
            }

            @Override
            public boolean ignoreTable(String tableName) {
                return tableName.startsWith("sys_menu") ||
                       tableName.startsWith("sys_dict");
            }
        }));
        return interceptor;
    }
}
```

## 七、敏感数据存储规范

### 7.1 加密存储字段

| 字段 | 加密方式 | 存储格式 |
|------|---------|---------|
| 手机号 | AES加密 | 加密值 + 脱敏值 |
| 身份证 | AES加密 | 加密值 + 脱敏值 |
| 密码 | BCrypt | 单向哈希 |

### 7.2 存储示例

```sql
-- 手机号
phone VARCHAR(128) DEFAULT NULL COMMENT '手机号(加密存储)',
phone_mask VARCHAR(32) DEFAULT NULL COMMENT '手机号(脱敏)',

-- 身份证
id_card VARCHAR(128) DEFAULT NULL COMMENT '身份证号(加密存储)',
id_card_mask VARCHAR(32) DEFAULT NULL COMMENT '身份证号(脱敏)',
```

### 7.3 脱敏规则

- 手机号：138****8888
- 身份证：110***********1234
- 姓名：张*三

## 八、SQL性能规范

### 8.1 性能级别说明

| 级别 | 说明 |
|------|------|
| system | 表只有一行 |
| const | 主键或唯一索引等值查询 |
| ref | 非唯一索引等值查询 |
| range | 索引范围查询 |
| index | 全索引扫描 |
| ALL | 全表扫描（避免） |

### 8.2 优化建议

- 避免全表扫描
- 避免索引失效（函数、隐式转换、左模糊）
- 控制JOIN表数量（不超过3张）
- 大分页使用延迟关联
- 批量操作控制数量
